# GAUNTLET.md — how the Ticino game gets built

Carried over from *After Dark* (`smirne/devoxx-gauntlet-m`, `GAUNTLET.md`), trimmed for a booth game
with no contest rubric. Every piece is produced by a **builder**, then judged by a **critic on fresh
context** who sees only the running build, never the builder's diff.

## 1. Architecture

```
src/sim/      2D, headless, tested. The only source of truth for game state.
src/sim/venue the Palazzo, digitised in metres; build.ts turns it into walls.
src/plan/     2D plan-check page (canvas). Reads sim only.
src/render/   robot rigs (Three.js, procedural). Reads sim only.
tests/        vitest. The acceptance criteria.
tools/plans/  PDF -> world-oriented PNG + vector trace.
```

Robots are procedural primitives with a bone rig and procedural gait — no GLB, no external assets.

unchanged (Michele, 2 Nov 2026). Changing one is a human decision, never a builder's.

## 2. Stages

### Stage 0 — seed (done, 2 Nov 2026)
Engine, rigs and their tests from After Dark; oriented walls; plans extracted.

### Stage 1 — the venue, verified in 2D
The Palazzo's public areas, both floors, digitised from the PDFs. Pass condition, all factual:
`tests/venue.test.ts` green (areas within 12% of the plan's m², every public room reachable,
building sealed), and Michele has driven the robots round the plan check and signed it off. Open
questions about the building (storey height, which rooms Voxxed Days actually uses, the booth
area) are answered or logged in `docs/venue.md`.

### Stage 2 — the robots, recognisable
Re-check the rigs against the model sheets (they came over verified; the check is that nothing
regressed). Critic places each robot face-on next to its sheet.

### Stage 3 — the game
Design the challenges for this building (`docs/` design doc, to be written with Michele), then
build them one at a time. Booth-first: short, restartable, readable from a step back.

### Stage 4 — 3D
Port After Dark's `src/render3d` onto the verified venue: materials and light from the photos.

### Stage 5 — booth and talk
Booth build (kiosk mode, attract loop, idle reset), talk material from `docs/genai-notes.md`.

## 3. The loop

**Builders** work one piece at a time; every handoff passes the suite.

**Critics** get fresh context every round. A critic launches the actual build (browser automation),
runs the factual checks first and fails the round outright if they fail, then judges craft, and
gives a verdict: better or worse, the single biggest gap. Cap 3 rounds per piece; the venue and the
robots escalate to Michele rather than ship failing.

**Publish a playable build after every significant round** and give Michele the link — always the
same artifact once one exists, built from the committed state, with what is known to be wrong.

---

## 4. Tests are the acceptance criteria

A test may be rewritten to assert better behaviour; it is never deleted or loosened to let a
regression through.

## 5. Per-session housekeeping

Append to `docs/genai-notes.md`: what the agent did, what a human decided, what was rejected and why.
